# Real-voice 回测指南（队友版）

> 一个文件讲清楚：怎么对线上后端做自动化回测、怎么读结果、出 bug 怎么报。

---

## 一、回测是什么

`backtest_20sessions.py` 会模拟 **N 个独立顾客**，每人完整走一遍点餐流程：

```
寒暄 → 人数口味 → 要推荐 → 下单 → 加单 → 换菜 → 加菜+结账(一句话) → 查单 → 寒暄 → 结束
```

共 10 轮消息。脚本自动做**三级校验**（不靠人眼）：

| 级别 | 校验方式 | 含义 |
|------|---------|------|
| 轮级 | 检查 AI 回复是否含回退/异常关键词 | 服务稳定性 |
| 会话级 | 10 轮全过 + 订单校验全对 | 整单体验 |
| 账目级 | 直接对照订单 API：金额=¥112、菜品={东坡肘子,冬瓜排骨汤,米饭}、已支付 | **一分钱不能错** |

预期金额链（脚本自动校验）：`下单¥18 → 加米饭¥24 → 换菜¥84 → 加汤结账¥112`

## 二、快速开始（3 步）

```bash
# 1. 拿代码
git clone git@github.com:Terrence20070515/Real-voice-mvp-cloudserver.git
cd Real-voice-mvp-cloudserver/tests

# 2. 改一个地方：打开 backtest_20sessions.py，把 SID_PREFIX 改成你的名字
#    SID_PREFIX = "teammate"   →   SID_PREFIX = "zhangsan"

# 3. 跑（python3.8+，零依赖）
python3 backtest_20sessions.py --sessions 20
```

约 20 分钟跑完，末尾输出报告。

## 三、常用参数

```bash
python3 backtest_20sessions.py \
  --base http://101.34.242.247:8080 \   # 后端地址（默认即线上）
  --sessions 20                          # 会话数，冒烟可先 --sessions 2
```

**建议**：第一次先 `--sessions 2` 冒烟，确认能通再跑 20。

## 四、怎么读报告

```
=== 20会话长链回测报告（200条消息, 耗时1306s）===
会话级准确率: 19/20 = 95%      ← 10轮全对且账目全对的会话占比
轮级成功率:   199/200 = 100%   ← 200条消息中无异常的比例
结账金额正确: 20/20 = 100%     ← 账目（最重要的商业指标）
订单项正确:   20/20 = 100%
回退/误判轮:  1                ← 异常轮的明细在下方列出
```

- **账目 100% 但会话级 <100%**：AI 说话措辞偶发异常但钱没算错，影响小
- **账目 <100%**：严重问题，立刻报 bug（附会话明细）

## 五、进阶：Self-Play 评测（可选，需要 DeepSeek key）

AI 扮演不同 persona 顾客（过敏/纠结/急性子等）自由对话，judge 模型打 1-5 分，
**≥4 分的对话自动蒸馏回灌示例池**（RLAIF 闭环）：

```bash
cd ai_training
pip install openai python-dotenv

# 生成 + 评测 + 自动回灌（一条命令完成闭环）
DEEPSEEK_API_KEY=sk-你的key python3 selfplay.py --sessions 8 --mode normal

# 两种模式
#   --mode normal  正常顾客（回归测试）
#   --mode hard    压力测试（挖 badcase：反复换菜、报过敏、试探型）
#   --no-distill   只评测不回灌
```

⚠️ **key 不要硬编码进代码**，只在命令行临时传。没有 key 的队友跳过这部分，
跑第一节的回测就够了。

## 六、红线（必读）

1. **session_id 必须带你的名字前缀**（改 `SID_PREFIX`）——会话历史按 sid
   持久化，裸跑会和别人/历史测试混淆，数据全废
2. **不要调 `/api/menu/import`**——那会改线上菜单，且菜单差异 >20% 会触发
   训练示例自动重生成，影响所有人
3. **不要清别人的订单**（订单是全局的，按 session_id 区分）
4. 单条 AI 回复 1-4 秒正常，**不要并发轰炸**后端
5. 测完的大批量订单留在表里没问题，但在群里说一声方便统一清理

## 七、发现 bug 怎么报

一句话模板（缺一不可）：

```
[bug] <现象一句话>
会话: <SID_PREFIX + 时间>
触发消息: <顾客说的原话>
AI 回复: <原话复制>
时间: <HH:MM>
```

后端对话日志在服务器 `data/conversations.json`（按 session_id 可回放），
报上来后我们能精确还原当时 AI 调了什么工具、参数是什么。

## 八、当前基线（2026-09-11）

| 指标 | 基线 |
|------|------|
| 会话级准确率 | 95%（19/20） |
| 账目正确率 | **100%**（20/20） |
| 回退/崩溃 | 200 条消息 0 次 |
| 示例池规模 | 525 条（RLAIF 自动回灌中） |

你跑出来的数字和基线差很多时，先检查是不是自己的网络/前缀问题，
再怀疑后端。
